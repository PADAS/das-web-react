## Resolved product decisions

1. **Layout — filters and grid**  
   Use **only the main grid area** (not the wide `tabsContainer` sidebar panel) for filters and the AG Grid workspace. The Data nav item still uses the vertical rail + close behavior like other tabs; primary content is the full-width data view where the map would be.

2. **Filter scope (initial)**  
   Start with the **same filters as the map/event feed** (and equivalent shared state where it already exists).

3. **Subjects — not map-window scoped**  
   Default: **tabular “full world” list** without requiring the current map bbox. Optional **checkbox** to restrict to **current map bbox** (map hidden on Data; bounds may still exist in memory).

4. **CSV export**  
   **v1** — AG Grid Community CSV export only (no Enterprise-only export).

5. **Drill-down — nested tabular, not event/patrol routes**  
   **Do not** navigate to `/events/:id` or `/patrols/:id`. Open **another nested tabular view** of contained structure (`event_details`, nested objects, arrays). AG Grid **Community only** (no Master/Detail Enterprise API).

6. **Drill-down — interaction (accessibility, locked)**  
   - **Primary:** explicit **Explore** / **Open structure** (per-row and/or toolbar when row selected) + **keyboard** (Enter / space on control).  
   - **Single-click:** **selection only**.  
   - **Double-click:** optional accelerator only; **not** the only path.

7. **Navigation between drill levels — breadcrumb (locked)**  
   **Breadcrumb** above grid or detail pane; segments (except last) **clickable**; **Back** pops one level; **Escape** pops one level when focus is in drill-down.

8. **Styling**  
   AG Grid CSS + Bootstrap / existing SCSS where practical.

9. **Permissions**  
   Gate like the rest of the app: events (`EVENTS`), subjects (`SUBJECTS`), patrols (patrol management + read permission).

---

## Technical constraints

- **`ag-grid-community`** + **`ag-grid-react`** only — no `ag-grid-enterprise`.
- Nested drill-down via nested grids, split panes, or full-width embedded grids — not Enterprise Master/Detail.

---

## Rationale (accessibility)

Double-click–only drill-down is hard for motor/touch users and often lacks a keyboard path. Single-click drill-down conflicts with row selection. The locked pattern (§6–7) matches common accessible grid practice: one clear activation, good labels, double-click as optional shortcut.
